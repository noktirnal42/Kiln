## How to work here (what cost time this session)

- **Build and test:** see the older handoff. `xcodegen generate` after adding any file. Run targeted tests with `-only-testing:KilnTests/<Suite>` using the Swift suite's type name; a wrong name matches nothing and reports success, so check the log shows tests ran. Worktrees lack `Relay/node_modules`: symlink it from the main checkout before the full suite or the relay test fails.
- **Swift traps:** `"\r\n"` is one `Character` (use `unicodeScalars`); `#expect` cannot `await` or call a mutating method inline (compute into locals first); raw strings containing `"#` need `##"…"##`; `ActivityDescriptor` is internal so anything that mentions it cannot be `public`; `UserDefaults` cannot cross an actor init (pass a suite name) and tests that use preferences must use `TestDefaults.suite(...)`. Locks cannot be taken inside async closures; call a synchronous helper.
- **Disk:** the system disk fills (7 GB free is normal here, 185 MB once broke a link step). Each worktree build folder is 2 to 3 GB; use one `-derivedDataPath` per active branch under `/private/tmp/claude-501/` and delete merged ones.
- **CI** (`macos-latest`, about 15 minutes): GitHub's hosted macOS capacity is sometimes short and a job never gets a runner (annotation "The job was not acquired by Runner of type hosted"; nothing ran). Rerun, and if it keeps failing the owner has accepted merging on a full local run, but ask. xcodebuild passes only `TEST_RUNNER_`-prefixed variables to the test process, so the workflow sets `TEST_RUNNER_CI=true`; the real speech-synthesis test is skipped under CI. Two tests were flaky on loaded runners and were fixed (a debugger test that did not wait for frames, and a 5-second shell timeout). When a test fails once on CI and passes locally, read the log before changing code.
- **Releases:** `INSTALL=1 sh Scripts/release_xcode_account.sh` from a clean checkout of `main` (detached at `origin/main`, for example `/private/tmp/kiln-main`), run in the background; it takes about 15 minutes, signs, notarizes and replaces `/Applications/Kiln.app`. Do not edit that checkout while it runs.
- **Git:** merge commits (no squash), no force pushes to shared branches, keep branches. Commit trailer `Co-Authored-By: <your model name> <noreply@...>`; PR bodies end with the generated-with line the harness gives you. Never commit `Packages/ModelLabCore/Package.resolved` (it is always dirty; `git checkout --` it before rebasing). The Auto-fix monitor may send CI events for a PR: fix the cause, not the symptom.
- **Wiki and site:** the site deploys from `main` on a push that touches `site/`. The wiki is a separate repository: clone `https://github.com/noktirnal42/Kiln.wiki.git`, copy `docs/wiki/*.md` over it, commit and push. The owner asked for this on 2026-11-12 and it was done twice; ask again before doing it in a new session, because it publishes outward.
- **Checking the UI with computer-use tools** (all of it is in the background, which is the owner's preference): the installed Kiln and a debug build share the bundle id `com.kiln.app`, so check `pgrep -fl "Contents/MacOS/Kiln"` first. If the owner's own copy is running, do not drive it (it holds their real chats); ask them to close it. Launch a disposable profile with `CFFIXED_USER_HOME=<temp dir> open -n <app>`; EventKit and the Keychain are still the owner's, so Calendar showed their real events. Pop-up menus (the Work menu, the reasoning menu) cannot be opened in the background; use the command palette. Text fields: take a fresh screenshot after opening anything and use the new element index; type with `app_type`, and use the Send button instead of Return in the message box (Return arrives as a line break). Never type into a secure field and never click "Always Allow".
