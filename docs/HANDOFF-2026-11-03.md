## Desktop / MCP work in progress

Working checkout: `/tmp/kiln-computer-use`, branch `codex/kiln-computer-use`, based on `origin/main` at `f360825`. It currently has **uncommitted experimental changes**. Review `git diff` and untracked files before continuing; do not assume they are release-ready.

- `ComputerUseTool.swift` is an initial native macOS Accessibility implementation: list running apps, inspect an accessibility tree, press an indexed element, or set an element value. It is opt-in (`computerUse.enabled`) and per-call approval gated; it blocks Kiln/System Settings and secure fields. It is **not yet equivalent to Codex/Claude**: no screenshots, coordinate interaction, keyboard, scroll/drag, full stale-element protection, accessibility permissions onboarding, or comprehensive security review. Compiled, but no real in-Kiln agent control has yet been verified.
- `MCPAgentTools.swift` adds generic agent-facing listing/calling of already approved, connected MCP servers. Calls are classified admin and require per-call review. This is experimental, not yet verified end to end or demonstrated with a server. Kiln previously displayed MCP tools in the UI but did not expose them to its agent.
- Kiln's mode ceiling previously capped all acting modes at `execute`; the experimental change makes narrow exceptions for `computer_use` and `mcp_call_tool` and uses review approvals. Review policy behavior, disabled profile handling, prompt injection and approval previews thoroughly before merging.
- Codex's private `SkyComputerUseClient mcp` server can enumerate its tool schemas, but an unauthenticated independent process receives `Sender process is not authenticated` on `get_app_state`. This is a host authentication boundary, not a permission to bypass it. Kiln must implement its own service.
- Kiln's skill catalog scans common Claude/Codex/OpenCode/Agents directories and Claude plugin caches, but does not fully import enabled Codex plugin skills or make vendor-bound connectors available. Codex config had 11 MCP server entries (10 enabled, computer-use disabled), 30 enabled plugins; Claude had 4 top-level MCP servers and 3 enabled plugins; OpenCode's JSON had 1 MCP entry. These are snapshots, not proof of working services or all connector access. Imported server configs still require connection and approval; authenticated vendor connectors may not be portable.
- Calendar question: Kiln's model said it cannot inspect Calendar because no computer-control or EventKit tool was offered. A separate Codex computer-use inspection saw only Election Day, all-day, on the visible calendars for Nov 3. This was **not** Kiln using its own tool.
- User requested bypass-permissions and automatic modes. They are **not implemented yet**. Design explicit, visible, revocable modes with precise scope; preserve macOS TCC and distinguish agent approval bypass from OS permissions, audit, network and connector permissions. Test no silent escalation and document tradeoffs. Do not claim safety or feature parity without verification.
