Agent profiles

Kiln exposes application services as ordinary tools. A profile chooses which are offered: Research Assistant is read-only, Coding Agent adds file, shell and Git tools, and Workstation Agent adds the module tools below. Each module declares the tool prefixes it owns in the activity registry, so a new activity does not need edits to shared files.

Approvals

Reads run freely. Writes, commands and network calls open an approval sheet; Allow once answers one call, and an Always Allow standing grant (revocable under Approvals) is made only at the Mac. The composer's Permissions menu offers three modes:

  • Ask (default) waits for you on every approval.
  • Auto approves routine calls: non-destructive, inside the project, not flagged by the execution policy, not admin tier. It has been unit-tested but not run by a real agent yet.
  • Bypass (red, confirmed first) approves everything except hard policy blocks and behavior-monitor holds; it was exercised by a real agent run.

A mode answers once, never creates a standing grant, never answers a monitor hold, and resets to Ask when Kiln launches. Decisions are written to the approvals log with how they were given, and mode changes go to the audit chain.

Kiln as an MCP server

Develop → MCP → Start exposes the same tool registry to external clients such as Claude Code, Codex or OpenCode. It listens on loopback only and requires a bearer token stored in a private file under Application Support. External calls run as “External: <client>”, are audited, and wait for approval in Kiln unless they are reads. A request without the token is refused with 401. The in-app agent also acts as an MCP client: it reads, never copies, servers and skills configured for Claude Code, Codex and OpenCode, and every imported server still needs Approve & Connect.

The tool list is generated from the registry, so it grows with the app; the authoritative list for any build is what tools/list returns.

Loading toolskiln_tool_searchpart of the agent loop, not a registered tool; runs nothing

More than 200 tools make about 21,000 tokens of definitions. When those would use more than a tenth of a model’s context window, a run starts with the file, search, shell, Git and web tools plus kiln_tool_search; the agent loads the others by asking, and a window too small even for the basics is trimmed to fit. Permissions and approvals are unchanged. It was seen working with one hosted model; the MCP server still offers every tool, and swarm workers get theirs up front.

Known gaps

The agent cannot operate every feature. The registry lists capabilities that have no agent tool yet, among them: starting or cancelling a swarm run, browsing or verifying the audit chain, selecting an analysis project, deleting projects or media, model download into the library, and browser history and tab closing. Shell access is not a substitute for a service-backed action. The capability matrix is the maintained list.

Tool names above were read from the source on main (2026-11-12); per-tool permission levels are given only where the repository documents them. Which tools a given model can use reliably varies; see known issues.
